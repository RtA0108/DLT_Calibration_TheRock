## 2. 수정 전 문제 상세

### A-1. 마커 생성 위치 (`Marker.cs`)
- `SetMarker()`가 `canvasRectTransform.anchoredPosition = canvasPosition`으로 **Canvas를** 옮기고 있었다. 마커 자신의 위치는 그대로였다.
- `ScreenPointToLocalPointInRectangle()`에 카메라로 `null`을 넘겼다. CanvasUI는 Screen Space - Camera라서 카메라를 넘겨야 올바른 좌표가 나온다.
- 드래그는 `anchoredPosition += eventData.delta` 방식이었다. 캔버스 1단위가 1픽셀이 아니면 마커가 포인터를 따라가지 못한다.

### A-2. 내부 파라미터 적용 (`DLT_solve.cs`)
- 초점거리를 `focalLength * (36 / Screen.width)`로 환산했다. `Screen.width`는 Display 1(조작 화면) 크기라서 프로젝터 해상도와 맞지 않는다.
- `lensShift = (cx / Screen.width) * 2 - 1`은 Unity 정의(센서 크기 대비 비율)와 맞지 않는다. x축 기준으로 크기가 2배이고 부호가 반대다. 실측으로는 Unity에서 lensShift.x = 0.08일 때 주점 cx = 268.8px(폭 640px), 즉 `lensShift.x = (W/2 − cx) / W`였다.
- fy(종횡비)와 skew는 계산만 하고 적용하지 않았다.
- 분해 계산을 `float`(`Vector3`)로 해서 정밀도가 부족했다.
- 외부 파라미터(위치/회전) 분해 자체는 맞았다. 실측에서도 위치와 회전은 정확히 복원됐다.

### A-3. 2D 좌표 기준 (`VertexInteraction.cs`)
- 마커 시작점과 GT를 `mainCam.WorldToScreenPoint()`(Display 1 픽셀)로 계산했다.
- 반면 드래그 후 좌표는 `projectCam` 기준(Display 2 픽셀)으로 저장됐다.
- 두 화면 해상도가 다르면(예: 1920x1080 vs 640x480) 같은 점이 전혀 다른 좌표가 된다.

### A-4. 대응점 짝 관리 (`VertexInteraction.cs`, `VertexClickTest.cs`)
- 2D 좌표는 `VertexInteraction`이 `arrayIndex`(현재 선택 개수) 슬롯에 썼다.
- 3D 좌표는 `VertexClickTest`가 "첫 번째 빈 슬롯"에 썼다.
- 선택을 한 번 해제하면 두 인덱스가 달라져 짝이 어긋났다.
- `copied` 플래그 때문에 한 번 선택했던 구는 다시 선택해도 2D 좌표와 마커가 생기지 않았다.
- 해제해도 마커가 지워지지 않았다.
- `VertexClickTest`는 Calibration 모드가 꺼져 있어도 3D 점을 추가했다(2D 좌표는 (0,0)으로 남음).

### A-5. 태그 중복 (`SampleScene.unity`)
- `Project Camera`와 `Capturet Camera`가 둘 다 `Project Camera` 태그였다.
- `FindWithTag("Project Camera")`를 쓰는 곳(`ProjectionMappingCalibrator`, `Marker` 등)이 어느 카메라를 잡을지 보장되지 않았다.

## 3. 좌표계 약속 (수정 후)

모든 계산을 **Unity 좌표계 그대로** 한다. 축을 뒤집는 변환은 없다.

| 항목 | 좌표계 |
|---|---|
| 3D 점 | Unity 월드 좌표 (구의 현재 `transform.position`) |
| 2D 점 | `projectCam`(프로젝터)의 스크린 픽셀 좌표. 좌하단 원점, y 위쪽. `Camera.WorldToScreenPoint()`와 같은 좌표 |
| 투영 행렬 P | 위 3D → 2D를 잇는 3x4 행렬, `P = λ K [R \| -R C]` |
| K | `[[fx, skew, cx], [0, fy, cy], [0, 0, 1]]`, 픽셀 단위 |
| R의 행 | 카메라의 `right`, `up`, `forward` (Unity Transform 축과 동일) |
| C | 카메라 중심 (월드 좌표) |

## 4. 파일별 변경 내역

### 4.1 `DLTcalibration/Assets/Script/DLT_solve.cs`

활성 코드(파일 상단)를 다시 작성했다. 하단의 주석 처리된 옛 코드는 그대로 두었다.

**삭제/교체**
- `CalculateAndApplyParameters()`, `ApplyIntrinsicsAndExtrinsics()`, `AdjustRotationForUnity()`, `AdjustForCoordinateSystem()`, `QuaternionFromMatrix()`
  → `SolveDLT()`, `TryDecompose()`, `ApplyToCamera()`, `BuildProjectionMatrix()`로 교체
- `CalculateResidual()`, `CalculateRMSE()` → `ReportResult()`로 교체
- 사용하지 않는 `using` 제거: `UnityEditor`(플레이어 빌드 컴파일 오류 원인), `Unity.VisualScripting`, `System.Transactions`, `UnityEngine.Rendering`, `UnityEngine.UIElements`, `System.Collections`

**`PerformDLT()`**
- 3D 좌표를 클릭 시점의 `worldCoordinate`가 아니라 **F를 누른 시점의 구 위치**에서 가져온다. 클릭 후 슬라이더로 모델을 움직여도 반영된다.
- 6개 상한(`Math.Min(pointCount, 6)`)을 없앴다. 선택한 점을 모두 써서 최소제곱으로 푼다. 최소 6개는 그대로.
- 점들이 거의 한 평면(또는 직선) 위에 있으면 경고한다(`PlanarityScore() < 1e-3`).

**`SolveDLT()` (신규)**
- DLL(`DLT_Rezero.dll`)의 `DLT()`는 그대로 쓴다.
- 호출 전에 Hartley 정규화를 한다.
  - 3D 점은 중심을 원점으로 옮기고 평균 거리를 √3으로 맞춘다.
  - 2D 점은 중심을 원점으로 옮기고 평균 거리를 √2로 맞춘다.
- 결과를 `P = T2⁻¹ · Pn · T3`로 원래 좌표계로 되돌린다.
- DLL이 `P[2,3] = 1`로 고정하는 방식이라, 정규화가 없으면 좌표 크기 차이 때문에 수치적으로 불안정하다.

**`TryDecompose()` (신규)**
- `double` 정밀도로 계산한다(내부용 `D3` 구조체).
- 점들이 카메라 앞(깊이 > 0)에 오도록 P의 부호를 맞춘다.
- Gram-Schmidt로 RQ 분해해서 `fx, fy, skew, cx, cy`와 `right, up, forward`를 구한다.
- `det(R) < 0`(좌우가 뒤집힌 해)이면 경고하고, P를 그대로 재현하도록 fx를 음수로 둔다.
- 카메라 중심 `C = -M⁻¹ p4`.

**`ApplyToCamera()` / `BuildProjectionMatrix()` (신규)**
- 위치와 회전: `SetPositionAndRotation(C, LookRotation(forward, up))`
- 내부 파라미터: `focalLength`/`lensShift` 대신 **`projCam.projectionMatrix`에 직접** 넣는다.
  ```
  m00 = 2·fx/W   m01 = 2·skew/W   m02 = 1 − 2·cx/W
  m11 = 2·fy/H   m12 = 1 − 2·cy/H
  m22 = −(f+n)/(f−n)   m23 = −2fn/(f−n)   m32 = −1
  ```
  W, H는 `projCam.pixelWidth/pixelHeight`, n, f는 카메라의 near/far.

**`ReportResult()` (신규) – 콘솔 로그**
- `[Calibration Info]`: fx, fy, skew, 주점, 화면 크기, 위치, 회전
- `[Reprojection]`: 적용된 `projCam`으로 3D 점을 다시 투영한 위치와 마커 위치의 RMSE/최대값(px)
- `[Residual]`: 마커 평균 이동량 (클릭 당시 투영 위치 GT에서 얼마나 옮겼는지)
- `[Sim]`: GT 2D 점으로 푼 카메라 대비 위치 오차, 회전 오차(°), fx 차이 (시뮬레이션 평가용)
- 기존 `[RMSE]`는 DLT 파라미터 11개끼리 비교한 값이라 의미가 없어서 삭제했다.

### 4.2 `DLTcalibration/Assets/Script/VertexClickTest.cs`

대응점 선택을 **슬롯 단위로 한 곳에서** 관리하도록 바꿨다. 슬롯 i에 다음이 항상 함께 묶인다.
- `clickedObjects[i]`: 선택된 버텍스 구
- `verticesStruct[i]`: 3D 좌표, 2D 좌표(`screenCoordinate`), 클릭 당시 투영 위치(`screenCoordinateGT`)
- `markers[i]`: 프로젝터 화면의 마커
- 구 색상(빨강 = 선택됨)

**추가된 것**
- `public MarkerManager markerManager`: 씬에서 CanvasUI의 MarkerManager를 연결해 둠. 비어 있으면 `CanvasUI`에서 찾는다.
- `private Marker[] markers`
- `ReleaseSlot()`: 슬롯을 비우고 마커도 삭제
- `ReleaseDestroyedSlots()`: 메쉬를 바꿔 선택돼 있던 구가 파괴되면, 다음 프레임에 그 슬롯과 마커를 자동 정리
- `SetSphereSelected()`: 구 색상 변경을 `VertexInteraction.SetSelected()`에 맡김

**변경된 것**
- `AddObject()`: 3D 좌표 저장, **`projectCam` 기준** 2D 투영(GT와 시작 위치), 마커 생성, 구 색상을 한 번에 처리한다. 투영 위치가 화면 밖이거나 카메라 뒤면 경고한다.
- `RemoveObject()`: 색상 복구와 `ReleaseSlot()` 호출
- `HandleClick()`: Calibration 모드(키 1)가 꺼져 있으면 무시
- 배열 크기를 `MaxPoints = 10`으로 통일 (`verticesStruct`는 12였음)
- `arrayIndex`(선택 개수) 필드는 `MoveVertex.cs`가 참조하므로 유지

### 4.3 `DLTcalibration/Assets/Script/VertexInteraction.cs`
- `OnMouseDown()`을 삭제했다. 마커 생성, 2D 좌표 저장, `copied` 플래그 모두 없앰.
- 선택 표시 색상만 담당하는 `SetSelected(bool)`을 추가했다.
- 초기화를 `Start()`에서 `Awake()`로 옮겼다.
- `newMeshPrefab` 필드는 프리팹 직렬화 데이터 보존을 위해 남겼다(사용 안 함).
- 하단의 주석 처리된 옛 코드는 그대로 두었다.

### 4.4 `DLTcalibration/Assets/Script/Marker.cs`
- `SetMarker(slot, screenPosition, canvasRect, cam, owner)`로 필요한 값을 모두 넘겨받는다. 태그나 이름(`FindGameObjectWithTag("Project Camera")`, `Find("LevelManager")`)으로 찾는 코드를 없앴다.
- 마커 번호는 `slot + 1`, 데이터 인덱스는 `slot`.
- 마커 위치를 **마커 자신의** `localPosition`에, 카메라를 넘긴 변환으로 설정한다(A-1 수정).
- `OnBeginDrag()`: 잡은 지점과 마커 중심의 차이를 기억해서, 드래그 시작 때 마커가 튀지 않게 함.
- `OnDrag()`: 포인터 위치를 캔버스 좌표로 직접 변환해 마커를 옮기고, 실제로 그려지는 프로젝터 픽셀 좌표를 `screenCoordinate`에 기록한다. 캘리브레이션 후 커스텀 투영 행렬이 들어가도 정확하다.
- `OnEndDrag()`(신규): 드래그가 끝나면 GT에서 얼마나 옮겼는지 한 번만 로그를 남긴다(기존에는 드래그 중 매 프레임 로그).

### 4.5 `DLTcalibration/Assets/Script/MarkerManager.cs`
- `CreateMarker(Vector2)` → `CreateMarker(int slot, Vector2 screenPosition, Camera cam, VertexClickTest owner)`. 생성한 `Marker`를 반환한다.
- 내부 카운터 `markerCount`를 없앴다. 번호는 슬롯으로 정한다.
- 프리팹이나 Canvas가 없으면 `null`을 반환한다.

### 4.6 `DLTcalibration/Assets/Scenes/SampleScene.unity` (2줄)
- `Capturet Camera`: 태그 `Project Camera` → `Untagged`
  - `ObjectCapturer`는 이 카메라를 Inspector 필드로 참조하므로 영향 없음
- `LevelManager > VertexClickTest.markerManager` = `CanvasUI`의 `MarkerManager`

### 4.7 인코딩 (`35f85e8`)

## 5. 검증 결과

Unity 에디터 플레이 모드에서, 실제 `PerformDLT()`, `AddObject()`, `RemoveObject()`, 마커 드래그 처리 함수를 호출해 검증했다.
- 기대값은 새로 만든 투영 함수가 아니라 **Unity 물리 카메라가 직접 계산한 투영**으로 만들었다(검증이 자기 자신을 참조하지 않도록).
- 조건: 프로젝터 화면 640x480(에디터 기본 Display 2), 비평면 3D 점 10개, 계산에 쓰지 않은 점 200개로 일반화 확인.

| 테스트 | 수정 전 | 수정 후 |
|---|---|---|
| 오차 없는 대응점으로 F → 같은 카메라가 나와야 함 (재투영 오차) | **258.54px** (최대 289px) | 위치 변화 0.0002, 회전 변화 0°, 미사용 점 200개 최대 0.0001px |
| 위치, 각도, 초점거리, lensShift가 모두 다른 "진짜 프로젝터"에 마커를 맞췄을 때 복원 | – | 위치 오차 0.0001, 회전 오차 0°, 미사용 점 200개 최대 0.0001px |
| 마커 표시 위치 vs 버텍스 투영 위치 | Canvas가 움직여 측정 불가 | 최대 0.0265px |
| 마커 드래그(잡은 점 오프셋 4px, 이동 (+37, −22)px, 커스텀 투영 행렬 적용 상태) | – | 기록 좌표 vs 기대 좌표 0.0075px, 기록 좌표 vs 화면 표시 0px |
| 선택 해제 후 다른 점 선택 | 짝 어긋남 | 같은 슬롯에 새 점 + 마커 번호 일치, 해제된 마커 삭제 확인 |
| 파괴된 구의 슬롯 자동 정리 | – | 다음 프레임에 슬롯 반환 확인 |

참고 측정 (점 6개 + 손 떨림 ±1px):
- 미사용 점 재투영 RMSE는 **1.12px**(최대 3.33px)로 작다.
- 그런데 카메라 **위치 오차는 5.26, 회전 오차는 4.94°** 로 크다.
- 초점거리와 거리가 서로를 보상하는 모호성 때문이다. 점 선택 방법을 평가할 때는 포즈 오차보다 **미사용 점의 재투영 오차**가 적절한 지표다. 6점은 노이즈에 취약하다.

검증하지 못한 것:
- 실제 Display 2 화면에서 마우스로 직접 드래그하는 것은 해보지 않았다(드래그 처리 함수를 같은 입력으로 호출해 검증).
- 실제 프로젝터와 물체를 이용한 캘리브레이션.

## 6. 사용 방법과 바뀐 동작

1. 드롭다운에서 모델을 로드한다.
2. **키 1**로 Calibration 모드를 켠다. 꺼져 있으면 버텍스가 선택되지 않는다.
3. Display 1에서 버텍스 구를 **6개 이상** 클릭한다. 같은 구를 다시 클릭하면 선택이 해제되고 마커도 사라진다.
4. Display 2(프로젝터)에서 각 마커를 실제 물체의 해당 지점으로 드래그한다.
5. **F**를 누르면 DLT를 풀어 `Project Camera`에 적용하고 콘솔에 결과를 출력한다.

주의:
- F 이후 `Project Camera`는 **커스텀 투영 행렬**로 렌더링한다. Inspector의 Focal Length, Lens Shift, FOV 값은 실제 렌더링과 무관해진다. 원래대로 되돌리려면 `projCam.ResetProjectionMatrix()`를 호출하거나 플레이를 다시 시작한다.
- 투영 행렬은 F를 누를 때의 프로젝터 해상도로 만들어진다. 이후 Display 2 해상도가 바뀌면 다시 캘리브레이션해야 한다.
- GT(`screenCoordinateGT`)는 "클릭 당시 프로젝터 카메라로 투영한 위치"다. 마커를 옮기지 않고 F를 누르면 카메라가 바뀌지 않는다.
