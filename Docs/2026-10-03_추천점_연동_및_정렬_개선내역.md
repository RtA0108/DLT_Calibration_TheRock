## 1. 요약

saliency로 추천한 점을 그대로 DLT 대응점으로 쓰고, 추가 장비 없이 사람이 실물에 맞추기 쉽게 만들었다.

| 구분 | 변경 | 결과 |
|---|---|---|
| 추천 → DLT 연결 | R 키로 추천점을 바로 대응점으로 선택 | 추천점을 다시 클릭할 필요 없음 |
| 추천 필터 버그 | 실루엣 마스크를 프로젝터 해상도로 생성 | 실루엣 일치 0% → 100%. 외곽선 근처 추천점 6개 중 4개 → 0개 |
| 추천 필터 추가 | 안쪽 가림 경계(깊이 끊김) 필터 | 바깥 윤곽선 필터가 못 잡던 안쪽 경계를 제외 |

| 정렬 방식 | 패치 마커(주변 모양을 맞춤), 정렬 보기 | 점 하나 대신 모양을 실물에 겹치게 맞춤 |
| 실시간 재계산 | 마커를 놓을 때마다 DLT 재계산 | 전체 투영을 보면서 조정 |

| 4D 텍스처 | 모델별 이미지 시퀀스 | 예전에는 처음 불러온 모델을 캥거루 텍스처로 덮어씀 |

| 모델 | Low poly TheRock 추가, 모든 모델 Read/Write | |

## 2. 사용 방법

1. 드롭다운에서 모델을 고른다. 프로젝터 화면의 50% 크기로 자동으로 맞춰진다.
2. **키 1**(캘리브레이션 모드) → **키 3**(추천점 표시).
3. 필요하면 **`-` / `=`** 로 추천점 개수를 조절한다(6~20).
4. **R**: 추천점을 대응점으로 선택한다. 가장 salient한 점이 1번이다.
5. **V**(정렬 보기)를 켜고, **T**로 패치 종류를 고른다.
   - 선: 흰색이나 단색 실물
   - 텍스처: 무늬가 있는 실물
6. Display 2(프로젝터)에서 패치를 끌어 모양이 실물과 겹치게 놓는다.
7. 6개 이상 놓이면 놓을 때마다 자동으로 다시 계산된다(**L**로 끄고 켬). 수동으로 풀려면 **F**.
8. V를 끄면 텍스처 투영 전체가 맞는지 볼 수 있다.

| 키 | 기능 |
|---|---|
| 1 / 2 / 3 | 캘리브레이션 모드 / 히트맵 / 추천점 표시 |
| `-` / `=` (숫자패드 −/+) | 추천점 개수 6~20 |
| R | 추천점을 대응점으로 선택 |
| T | 패치 선 ↔ 텍스처 |
| V | 정렬 보기 (모델 없이 마커와 패치만 투사) |
| L | 실시간 재계산 켜고 끄기 |
| F | DLT 계산 |
| P | 4D 텍스처 재생/정지 (텍스처 패치로 맞출 때 화면 고정) |
| H | 도움말 |
| F5 | saliency Python 다시 실행 |

입력칸에 글자를 치는 중에는 단축키가 동작하지 않는다.

## 3. 기능별 변경

### 3.1 추천점 → 대응점 (R 키) — `b571c33`
- `ProjectionMappingCalibrator.GetRecommendedPositions()`: 표시 중인 추천점의 현재 월드 좌표
- `CreateSphereAtVertex.FindSphereAt()`: 좌표에 가장 가까운 버텍스 구
- `VertexClickTest.SelectRecommendedVertices()`: 기존 선택을 비우고 추천 순서대로 슬롯을 채운다.
  - 키 1과 키 3이 켜져 있을 때만 동작한다. 꺼져 있으면 무엇을 켜야 하는지 경고한다.
  - 추천점이 프로젝터 화면에서 20px 안에 몰려 있으면 모델을 키우라고 경고한다.
- `VertexClickTest.ClearSelection()`: 모든 선택과 마커 해제

### 3.2 추천 파이프라인 수정

**실루엣 마스크 해상도** — `beb14b5`
- `SilhouetteEdgeMaskRenderer`가 마스크를 `Screen` 크기(Display 1)로 만들고, 조회는 프로젝터 픽셀 좌표로 했다. 그래서 엉뚱한 위치를 검사해 외곽선 필터가 사실상 동작하지 않았다.
- 대상 카메라의 `pixelWidth/pixelHeight`로 만들도록 고쳤다.
- Chick(스케일 150): 버텍스 투영이 실루엣 위에 떨어지는 비율 0% → 100%. 외곽선 1.8px 이내였던 추천점 4개가 모두 기준 밖으로 바뀌었다.
- 2025-06-12 "해상도 수정 1", "Silhouette filter 정상화?" 커밋에서 겪은 문제와 같은 원인으로 보인다.

**안쪽 가림 경계 필터** — `1aab332`
- 바깥 실루엣 필터는 날개가 몸통 앞에 겹친 경계 같은 안쪽 경계를 잡지 못한다.
- 프로젝터 시점 깊이를 그려서 이웃 픽셀 깊이가 2% 넘게 끊기는 곳 근처의 점을 뺀다.
- 설정: `ProjectionMappingCalibrator.useOcclusionEdgeFilter`, `occlusionDepthRatio`(기본 0.02)
- 새 셰이더 `Hidden/LinearDepthColor`(클립 공간 w를 깊이로 출력)
- Robot: 보이는 버텍스 2,923개 중 171개 제외(허벅지 안쪽, 허리 경계, 손가락), 4ms.

**최종 필터 순서:** 가시성(노멀 60° 이내 + 레이캐스트) → 실루엣 외곽선 → 안쪽 가림 경계 → 면 방향(≥ 0.3) → `Score = Saliency × D/L` 가중 FPS

**그 밖**
- `ProjectionMappingCalibrator.Run`에서 에러를 삼키던 `catch {}`가 이제 로그를 남긴다.
- `SaliencyUtils.GetVisibleVertices`: 버텍스마다 `mesh.normals` 전체를 복사하던 것을 한 번만 읽도록 했다(2,747ms → 11ms, 결과 동일).
- `SaliencyUtils.FilterVerticesByEdge`: 매 호출 만들던 `Texture2D`를 정리한다.

### 3.3 추천점 개수 조절 — `1aab332`
- `MainController.recommendedVertexCount`(6~20), 실행 중 `-` / `=` 키, UI의 `[-] n [+]`
- 개수만 바뀌면 필터와 saliency 계산 결과를 재사용하고 FPS만 다시 돌린다(`ProjectionMappingCalibrator.Reselect`). Robot: 21초 → 4ms.
- FPS는 순차 선택이라 개수를 늘려도 앞의 점은 그대로이고 뒤에 추가된다. 6개일 때의 점이 9개일 때의 앞 6개와 같다.
- 대응점 슬롯 수 `VertexClickTest.MaxPoints`를 10 → 20으로 늘렸다.

### 3.4 패치 마커 — `7d5da4c`, `871c6df`
점 하나를 찾는 대신 **주변 모양이 실물과 겹치도록** 맞춘다. 패치 중심이 대응점이 된다.

- `PatchSnapshot`(신규): 현재 프로젝터 카메라 시점으로 렌더링해서 각 버텍스 주변(기본 64px)을 잘라 마커에 붙인다.
  - **선 모드:** 보이는 실루엣 외곽선 + 기준 각도보다 크게 꺾인 모서리. 깊이 테스트로 가려진 선을 빼고, UV 이음새로 생긴 가짜 경계를 없앤다. 배경 투명.
  - **텍스처 모드:** 프로젝터가 실제로 비출 화면 그대로. 불투명.
  - 모델 레이어만 그린다(버텍스 구, 추천 마커 제외).
  - DX11에서 렌더 텍스처를 부분만 읽으면 세로가 뒤집혀서, 전체를 읽은 뒤 CPU에서 잘라낸다.
- `Marker`: 패치는 마커들보다 아래 층(`PatchLayer`)에 두어 점과 번호가 가려지지 않게 했다. 번호는 패치 왼쪽 위, 흰색.
- `PatchDragForwarder`(신규): 패치 어디를 잡아도 마커가 드래그되도록 입력을 전달한다.
- **모서리 기준 각도 자동 결정** (`871c6df`): 모델 메쉬의 모서리 꺾임 각도 중앙값으로 정한다.
  - 중앙값 10° 미만(매끈한 high poly) → 35°
  - 그 외(각진 low poly) → 중앙값 × 0.8을 10~35°로 제한
  - 우선순위: Inspector `VertexClickTest.patchCreaseAngle`(> 0) → 라이브러리 `patchCreaseAngle`(> 0) → 자동
  - 모델마다 한 번 `[Patch] 선 패치 모서리 기준` 로그를 남긴다.

| 모델 | 면 수 | 꺾임 각도 중앙값 | 기준 |
|---|---|---|---|
| high poly 11개 (Chick, Horse, Kangaroo 등) | 32,868 | 0.1° ~ 5.7° | 35° |
| TheRock (low poly) | 492 | 21.0° | 16.8° |

### 3.5 실시간 재계산과 마커 위치 유지 — `6aea75f`
- **버그 수정:** CanvasUI는 카메라에 붙은 캔버스(Screen Space - Camera)다. 그래서 캘리브레이션으로 카메라가 바뀌면 옮기지 않은 마커도 화면에서 7~17px 움직였다.
  - 드래그 중이 아니면 매 프레임 저장된 프로젝터 좌표에 다시 놓도록 고쳤다(차이 0.02px 이하).
- **실시간 재계산:** 점이 6개 이상이면 마커 드래그가 끝날 때마다 DLT를 다시 풀어 적용한다(L 키). 로그는 한 줄 요약이다.
- 다시 풀 때마다 패치를 새 카메라 기준으로 다시 잘라 갱신한다.
- **불일치 경고:** 점이 7개 이상이고 서로 3px 넘게 맞지 않으면 경고한다(`DLT_solve.InconsistencyWarnPixels`).
  - 어느 마커가 틀렸는지는 지목하지 않는다. 처음에 만들었다가 뺐다.
  - 3번 마커를 일부러 12px 잘못 놓았는데 2번이 가장 크게 나왔다. 하나 빼고 풀기 방식도 마찬가지였다.
  - DLT 미지수가 11개라 점 10개 이하에서는 최소제곱이 오차를 다른 점에 떠넘기기 때문이다.
- `DLT_solve.PerformDLT(bool verbose)`를 public으로 바꾸고, 재투영 오차 계산을 함수로 분리했다.

### 3.6 히트맵 동기화 — `512052b`

- Chick: saliency와 히트맵 색의 상관 0.93

### 3.7 모델 크기 자동 맞춤 — `1aab332`
- 모델을 불러오면 프로젝터 화면 높이/너비의 50%를 차지하도록 스케일을 맞추고, 스케일 슬라이더와 입력칸에도 표시한다.
- 설정: `MainController.autoFitOnLoad`, `autoFitFraction`(기본 0.5)
- 예전에는 Chick이 프로젝터 화면에서 1.4px로 시작해서 추천점과 마커가 겹쳤다.

### 3.8 성능 — `17bd5b8`
- `SaliencyDataLoader`가 버텍스마다 모든 버텍스와 거리를 비교했다(Chick 기준 약 3억 번, 추천이나 히트맵을 돌릴 때마다 반복).
- 0.001 크기 격자에서 주변 27칸만 보도록 바꿨다. "0.001 이내 가장 가까운 점" 규칙은 그대로라 결과가 같다.
- 검증: Chick 17,599개, Robot 20,066개 값이 모두 같다.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 매핑 구축 | 약 6.9초 | 76ms |
| 조회 | 약 7.1초 | 22ms |
| 추천 계산 (Robot) | 약 21초 | 131ms |
| 히트맵 | 약 11초 | 108ms |

### 3.9 4D 텍스처 (모델별) — `dfb51b9`, `871c6df`
- 예전 `KangarooTextureAnimator`는 태그로만 모델을 찾아서, 처음 불러온 모델이 무엇이든 캥거루 텍스처 24장을 덮어썼다.
- `TextureSequenceAnimator`로 이름을 바꾸고(스크립트 GUID 유지, 씬 연결 그대로), 모델을 불러올 때 그 모델의 시퀀스만 재생한다. 없으면 원래 텍스처를 유지한다.
- **새 모델에 4D 텍스처를 붙이는 방법:**
  - `Assets/Resources/4D_Textures/<모델 id>/`에 이미지 시퀀스를 넣으면 자동 재생된다.
  - 또는 `DefaultLibrary.txt` 항목에 `animatedTexturePath`(Resources 경로 또는 디스크 절대 경로)와 `animatedTextureFps`(기본 24)를 적는다.
  - 재생 순서는 파일 이름순이고, 숫자는 크기순이다(`frame_2` < `frame_10`).
- P 키로 재생/정지한다.

### 3.10 UI — `bf92e53`
- `CalibrationHUD`(신규, Canvas에 부착, 실행 시 UI 생성)
  - 오른쪽: 추천점 개수 `[-] n [+]`
  - 왼쪽 아래: R, V, T, L, F, P, H 버튼. 각 줄에 현재 상태를 표시하고, 버튼은 키와 똑같이 동작한다. 아래 줄에 선택된 대응점 개수와 안내가 나온다.
  - 도움말 창(H): 사용 순서와 키 설명. 클릭하면 닫힌다.
  - 한글 표시를 위해 Windows 기본 글꼴(맑은 고딕)을 실행 시 불러온다. 없으면 Arial.
- `HotkeyGuard`(신규): 입력칸에 글자를 치는 중에는 단축키를 무시한다. 예전에는 스케일 입력칸에 "1"을 치면 캘리브레이션 모드가 같이 토글됐다.
- `VertexClickTest`: UI를 클릭할 때 뒤에 있는 버텍스 구가 같이 선택되지 않게 했다.

### 3.13 saliency 백그라운드 계산
- 예전에는 결과 파일이 없는 모델을 불러오면 `PythonProcessManager`가 메인 스레드에서 Python이 끝날 때까지 기다렸다. 그래서 Unity가 15초쯤 멈췄다.
- `SaliencyJob`(신규): CfS-CNN(Windows python)과 TexMesh(WSL)를 백그라운드 스레드에서 차례로 실행한다.
  - 없는 결과만 계산한다(예전에는 하나만 없어도 둘 다 계산).
  - stdout과 stderr를 동시에 읽는다. 예전처럼 하나씩 끝까지 읽으면 다른 쪽 버퍼가 차서 멈출 수 있었다.
  - Python 출력을 UTF-8로 읽는다. WSL 쪽 한글 로그가 깨지지 않는다.
  - 정상 종료인데 stderr에 나온 내용은 에러가 아니라 경고로 남긴다.
  - 결과 파일이 이번 계산에서 새로 써졌는지까지 확인해서 성공을 판단한다.
- `MainController`
  - 모델은 바로 쓸 수 있다(크기 맞춤, 버텍스 구, 수동 선택).
  - 계산 중에는 추천점(키 3)과 히트맵(키 2)을 내려 둔다. 끝나면 켜져 있던 것을 새 결과로 자동 계산한다.
  - F5(다시 계산)도 백그라운드로 돈다. 계산 중에 다시 누르면 경고만 한다.
  - 계산 중에 다른 모델로 바꾸면, 이전 계산은 결과 파일만 저장한다.
- `SaliencyDataLoader.ClearCache()`: 캐시가 경로로만 구분돼서, F5로 같은 파일을 다시 써도 예전 값을 쓰던 문제를 막는다.
- 조작 화면 상태 줄에 `saliency: TexMesh 계산 중... 8초`처럼 진행 상황을 표시한다. 계산 중에 R을 누르면 기다리라고 안내한다.

### 3.14 새 모델 추가 도구
메뉴 **Tools > 캘리브레이션 > 새 모델 추가** (`Assets/Editor/ModelImportWindow.cs`). OBJ를 고르면 아래를 한 번에 한다.
사용하는 사람을 위한 설명은 [DLTcalibration/새_모델_추가_방법.md](../DLTcalibration/새_모델_추가_방법.md)에 있고, 창의 **사용법** 버튼으로도 열린다.

1. OBJ, MTL, 텍스처를 `Assets/Resources/Meshes/<id>/`로 복사한다. OBJ 이름은 `<id>.obj`다(saliency 결과 파일 이름이 OBJ 이름을 따름).
2. 텍스처를 연결한다.
   - MTL이 있으면: `map_Kd` 등 텍스처 줄의 파일을 같이 복사하고 경로를 파일 이름만 남긴다. 파일 이름 대소문자는 구분하지 않는다.
   - MTL이 없으면(TheRock 경우): 고른 이미지로 MTL을 만든다. 이미지를 고르지 않았으면 OBJ와 이름이 같은 이미지, 아니면 폴더에 하나뿐인 이미지를 쓴다.
   - 재질 지정(`usemtl`)이 없으면 첫 면 앞에 넣는다. 없으면 Unity가 텍스처를 연결하지 않는다.
3. 메쉬 Read/Write를 켠다.
4. 실제 실행과 같은 `Resources.Load`로 불러와서 버텍스 수, Read/Write, 텍스처 연결을 확인한다.
5. `DefaultLibrary.txt` 맨 아래에 항목을 추가한다. 기존 줄은 건드리지 않고 끼워 넣은 뒤, 읽히는지 확인하고 저장한다.
6. (선택) 4D 텍스처 이미지 시퀀스 폴더를 `Resources/4D_Textures/<id>/`로 복사한다. 복사하지 않으면 원래 폴더 경로를 `animatedTexturePath`에 적는다.
7. (선택) saliency를 백그라운드로 계산하고, 값 개수가 OBJ 버텍스 수와 같은지 보여준다.

- id가 이미 있으면: 같은 모델이면 덮어쓸지 묻고(라이브러리 항목은 그대로), 다른 모델이 쓰는 id면 거부한다.
- saliency를 계산하지 않았는데 같은 이름의 예전 결과가 있으면 그게 그대로 쓰인다고 경고한다.
- 다른 모델처럼 OBJ와 `Meshes` 아래 PNG는 `.gitignore`에 걸려 git에 들어가지 않는다.
