# 연구 파이프라인 정리

- 기준일: 2026-10-06
- 적용 범위: 석사논문 1차 발표 및 이후 방법 정리
- 대표 결과: E237 오디오 조건 30초 UV 비디오 텍스처
- 파이프라인 도식: [`figures/01_pipeline.svg`](figures/01_pipeline.svg)

## 1. 연구를 한 문장으로 설명하면

고정 3D 메시의 의미 있는 표면 영역을 사건의 공간 제약으로 사용하고, 부위별로 제작한 생성형 시간 사건을 오디오 특징에 따라 선택·배치·중첩하여, 원본 메시의 UV에 적용할 수 있는 오디오 조건 비디오 텍스처를 생성하는 연구다.

현재 문서에서는 `MSR`을 **Mesh Semantic Region**으로 표기한다. 이는 의미 분할의 정답 label이 아니라, 사건의 위치·소유권·보호 범위와 저작 역할을 표현하는 수정 가능한 mesh surface 영역이다. 저장소 전체 용어 통일은 별도 작업으로 남긴다.

## 2. 연구 입력 구조

연구 파이프라인이 소비하는 정보는 사용자 외부 입력, 사전 제작 자산, 시스템 내부 파생 정보로 구분한다.

| 구분 | 항목 | 역할 |
|---|---|---|
| 외부 입력 | 고정 mesh와 UV | 사건을 결속할 물체 형상과 canonical surface 좌표 |
| 외부 입력 | 사용자 prompt | 원하는 재질, 분위기, 사건 문법과 금지 조건 |
| 외부 입력 | audio file | 사건의 시간 편성을 결정할 신호 |
| 파생 문맥 | mesh/audio 특징 기술 | 생성 prompt에 넣는 물체 부위·형상·음향 특성 |
| 사전 제작 자산 | 기본 texture | 사건 이전부터 유지되는 물체 전체 appearance |
| 파생 공간 정보 | MSR, 연속 alpha, owner, 보호 영역 | 사건의 허용 위치, 경계, 충돌 방지 |
| 생성 자산 | 부위별 temporal event source | 각 영역에 등록할 시간 RGB 변화 |

`owner`는 사용자가 따로 준비하는 입력이 아니다. MSR과 UV에서 파생되며, 각 texel을 어느 사건이 변경할 수 있는지 제한한다. 서로 다른 owner의 사건은 동시에 진행할 수 있지만 같은 texel을 중복 소유하지 않는다.

## 3. 연구 핵심 파이프라인

```text
[입력 및 사전 제작 자산]
고정 mesh+UV + MSR/owner + 사용자 prompt와 mesh/audio 특징 기술
+ 프롬프트로 제작·선정한 기본 texture + audio file

  ├─ [공간 사건 경로]
  │    부위별 정적 peak 후보 제작
  │    → temporal RGB event source 생성
  │    → 고정 mesh UV 등록
  │    → owner·보호 영역·경계 검사
  │
  └─ [시간 편성 경로]
       audio의 micro/meso/macro 특징 분석
       → 사건 종류·시작·중첩·생략 계획
                         │
                         ▼
            기본 texture 위 지속형 UV 합성
            · 등록된 source를 원래 순서와 속도로 사용
            · 서로 다른 owner의 동시 사건 허용
            · 사건 뒤의 변화 상태를 필요에 따라 유지
            · 원본 geometry와 비사건 영역 보존
                         │
                         ▼
       [최종 연구 산출물]
       오디오 길이에 대응하는 UV 비디오 텍스처
       + 동기 오디오 + 사건 시간표 + provenance/QA
```

### 3.1 부위별 사건 source 생성

사용자 prompt, mesh 특징, audio 특징의 언어적 기술을 바탕으로 부위별 사건의 peak appearance와 시간 변화를 제작한다. 현재 구현은 pretrained image/video generation을 사용하며 별도의 모델 학습이나 fine-tuning은 하지 않는다.

생성 모델은 **사건의 외형과 내부 시간 변화**를 만든다. 생성된 RGB를 곧바로 최종 화면으로 사용하지 않고, 다음 단계에서 고정 메시 표면과 UV에 등록한다.

### 3.2 3D/UV 등록과 공간 제약

생성 사건을 MSR의 연속 alpha와 owner를 사용해 고정 메시의 canonical UV에 등록한다.

- 원본 geometry를 변형하지 않는다.
- owner 밖의 texel과 보호 영역은 변경하지 않는다.
- 서로 다른 부위 사건의 침범과 충돌을 검사한다.
- 경계가 hard cut처럼 보이지 않도록 연속적인 공간 가중치를 사용한다.
- 최종 결과는 카메라 영상이 아니라 메시가 재사용할 수 있는 UV-domain 영상이다.

### 3.3 오디오 분석과 사건 편성

오디오 분석은 여러 시간 규모의 특징을 만든다.

- micro: onset, attack, 순간적인 percussive 변화
- meso: brightness, high-frequency detail, harmonic sustain, density
- macro: section novelty, 장기적인 방향 전환, 축적과 방출

이 특징들은 사건 후보별 점수와 threshold에 연결된다. 편성기는 다음을 결정한다.

- 어떤 부위 사건을 사용할지
- 언제 시작할지
- 서로 다른 owner의 사건을 동시에 시작할지
- trigger가 약할 때 아무 사건도 시작하지 않을지

현재 구조에서 raw audio latent를 LTX에 직접 입력하지 않는다. 따라서 오디오가 생성 영상의 모든 프레임을 end-to-end로 직접 만드는 방식이 아니다.

### 3.4 지속형 UV 합성

기본 texture를 지우고 전체 화면을 다른 이미지로 교체하는 방식이 아니라, 등록된 지역 사건을 원래 source 순서와 속도로 기본 texture 위에 합성한다. 사건 사이에는 기본 재질과 물체의 위치적 정체성을 유지한다.

동시에 여러 사건이 진행될 수 있으며, owner가 다른 사건은 병렬로 합성된다. 사건 종료 뒤에는 설계된 상태를 유지할 수 있어 단순한 반복 dissolve나 항상 초기 texture로 돌아가는 표현을 피한다.

## 4. 오디오가 결정하는 것과 결정하지 않는 것

| 오디오가 결정하는 항목 | 현재 오디오가 결정하지 않는 항목 |
|---|---|
| 사건 종류와 부위 | source 영상의 정확한 frame 수 |
| 사건 시작 시각 | LTX 내부 motion의 세부 궤적 |
| 동시 사건과 중첩 | 정적 peak 후보의 미적 성공 여부 |
| 약한 trigger의 생략 | owner와 보호 영역의 공간 정의 |
| prompt에 포함할 음향 의미 | 기본 texture 자체의 최종 선택 |

LTX 사건 source 길이는 연구자가 모델 호환 범위 안에서 지정한다. E237에서 사용한 `73/97/145` frame과 최종 `30초`는 현재 구현 사례의 값이며, 연구 방법 자체의 고정 길이가 아니다.

## 5. 최종 연구 산출물

핵심 산출물은 다음 묶음이다.

1. 고정 메시의 UV 좌표에 적용하는 비디오 텍스처
2. 비디오와 동기화된 원본 오디오
3. 사건 종류·시작·종료·중첩을 기록한 시간표
4. 입력과 생성 source의 provenance
5. owner 침범, 보호 영역, UV 경계와 재생 조건을 확인하는 QA 정보

MP4는 이 비디오 텍스처를 전달하고 재생하기 위한 한 형식이다. 연구 결과의 본질은 WebGL 화면이나 특정 Unity 장면이 아니라, 동일한 원본 메시 UV에서 재사용 가능한 시간적 texture다.

## 6. WebGL·Unity·프로젝터의 위치

이 세 단계는 핵심 생성 파이프라인 이후에 결과를 소비한다.

| 단계 | 연구에서의 역할 | 생성 결과 자체인가 |
|---|---|---|
| WebGL viewer | 메시 위에서 다각도 관찰, 시간 탐색, 시각 QA | 아니오 |
| Unity | 원본 mesh material에 비디오 텍스처 재생, 오디오 동기와 장비 연결 확인 | 아니오 |
| DLT/projector | 실제 물체와 프로젝터의 대응점 보정, 투사 오차와 물리 품질 평가 | 아니오 |

따라서 발표에서는 `UV 비디오 텍스처 생성`을 연구 본체로 제시하고, WebGL·Unity·DLT는 검증과 적용 가능성을 보여 주는 후단으로 구분한다.

## 7. E237에서 확인된 구현 사례

E237은 위 파이프라인을 TheRock 고정 메시와 30초 오디오에 적용한 현재 대표 사례다.

- 기본 appearance: walnut + amber resin 계열 나무 texture
- 사건 owner: 전면, 눈, 코, 귀, 입, 후면·정수리
- 오디오 편성: 사건 시작, 동시 사건, 빈 trigger 포함
- 생성 source: 전면·눈·코는 새로 생성하고 귀·입·후면은 검수된 기존 source 유지
- 최종 출력: 720 frame, 24 fps, 30초 UV 비디오 텍스처와 동기 오디오
- 고정 geometry와 비사건 영역 보존
- WebGL 3D QA와 Unity material 적용·재생 smoke test 완료
- 실제 projector–실물 오차 측정은 후속 physical validation 단계

E237은 연구 방법의 사례이지 파이프라인 정의 자체는 아니다. 다른 mesh와 audio에서 MSR, 사건 source, 편성 결과가 어떻게 일반화되는지는 별도의 평가가 필요하다.

## 8. 현재 한계와 다음 검증

- 사건 source의 길이와 내부 motion은 아직 오디오에서 자동 결정되지 않는다.
- 일부 사건은 오디오마다 새로 생성하지 않고 검수된 source를 재사용한다.
- 전면처럼 넓은 영역은 구조 사건보다 dissolve로 읽힐 위험이 있다.
- 작은 눈·코·입 사건은 해상도, UV sampling과 실제 투사 거리에서 약해질 수 있다.
- 한 메시와 한 오디오 사례만으로 cross-mesh·cross-audio 일반화를 주장할 수 없다.
- MSR 자동 제안과 사용자 수정 과정의 시간·조작량 평가는 아직 필요하다.
- aligned audio와 time/role shuffle 비교를 통해 오디오 인과성을 검증해야 한다.
- Unity 재생 검증과 실제 projector calibration의 물리 오차 측정은 구분해야 한다.

## 9. 발표에서 사용할 핵심 문장

> 본 연구의 결과는 WebGL에서 재생되는 3D 영상이 아니라, Mesh Semantic Region의 공간 제약과 오디오 사건 편성을 결합해 생성한 UV 비디오 텍스처다. 생성형 모델은 부위별 사건 source를 만들고, 오디오는 사건의 종류·시작·중첩·생략을 결정한다. WebGL·Unity·프로젝터는 이 산출물을 확인하고 적용하기 위한 후단이다.
